Written pick (3 pros / 3 cons each)

Winner: B (Focused) — F1/F2 build on this shell; A becomes theme-plugin candidate

Variant A prosVariant A cons
Fastest GM navigation: persistent tree + backlinks rail, zero clicks to jump.Sidebar noise: two always-visible rails overwhelm new players and guests.
Densest sheet/VTT scan: 3-stat grid + side initiative suit power users.No mobile story: 3 fixed columns squeeze the page below 320px; phone would need a redesign, not a reflow.
Secret context always visible: right rail shows access/backlinks without opening anything.Secret badge competes with two rails for attention; redaction less prominent in a busy frame.
Variant B prosVariant B cons
Mobile proven: single column reflows; B-08 shows one-handed sheet + ≥48px targets.Tree-less navigation bets everything on search/autocomplete quality (build-phase risk).
Lowest sidebar noise: collapsed drawer = zero chrome for new players; secret states read at a glance.GM power users lose one-click tree jumps; drawer toggling adds a step per lookup.
Keyboard path simplest: linear order (nav → main → actions → drawer summary → footer) with native details/summary.Drawer open-state persistence across SSE morphs needs a focus-retention decision in F1.

Decisive factor: G1 requires mobile stills and the product serves new players on phones; only B proves that. A’s density survives as a theme plugin (3-column override), which is exactly what p00 prescribes for the loser.
