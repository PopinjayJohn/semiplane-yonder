# P11 Auth + Users + Hosting Modes

## Goal
Local-first multi-user for GM + players on server or laptop.

## Scope
- Sessions locked Option A: stdlib HMAC-signed cookies (`session_id|user_id|expiry|hmac_sha256`, random 128-bit id in `auth_sessions{id,user_id,expiry,last_seen,revoked}`), `HttpOnly/SameSite=Lax`, `Secure` only for configured trusted proxies serving HTTPS / `X-Forwarded-Proto: https` (explicit allowlist; off on plain LAN with logged warning), 30-day absolute + 24h sliding idle expiry, key file `<data-dir>/.sessionkey` (0600 POSIX, best-effort ACL + note on Windows, never inside the vault) + rotation via `rotate-session-key` CLI (previous key honored 7d), `users.session_version` for revoke-all. Behind `SessionStore` interface so scs/library can replace later without touching handlers. CSRF double-submit incl. login POST. scs rejected: bundled sqlite3store needs mattn/cgo, conflicts with modernc lock.
- Config precedence: flags > env > defaults. Session key generated on `init` (0600 file), never logged. Passwords: argon2id `m=65536 (64MB), t=3, p=4`, 16-byte salt, 32-byte key, PHC string storage, rehash-on-login on param change.
- Invite flow: `init` creates the first GM account (flags); GM creates players + assigns `characters/<pc>/`; shareable wizard link (P07). CLI `reset-password` exists from day one (no email in v1).
- Non-secret pages open to guests; secret pages GM + owner/editable-by only (login wall). No `public` flag in v1.
- Laptop LAN (mDNS doc) + dedicated server (reverse-proxy doc, GM owns TLS). No built-in ACME for v1.

## Pass/fail
- Wiki test: guest reads non-secret, blocked on secret page (owner still reads own secret); player reads shared, writes only own subtree.

## Out
OAuth, password reset via email, per-player secrets (P06 plugin).
