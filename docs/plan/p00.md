# P00 UI Prototype

## Goal
Lock shell + secret UX + player IA before DB/rules. Purely visual, no functionality.
Static mockups only — no backend, no Datastar, no SSE, no working toggles/buttons.
First step: test 2 frontend design variants as static pages.

## Design variants (first step)
Static HTML/CSS only, switchable via `?design=a|b` (separate static renders, no shared logic):
- **A Obsidian-like:** left vault tree, center page, right backlinks/secrets. Dense, GM-power-user.
- **B Focused:** top nav + single column + collapsible right drawer. New-player friendly, mobile-first. Must prove one-handed sheet + tap-size dice/tokens on phone stills.

Only A vs B. Loser becomes theme plugin candidate.

Compare: navigation speed, secret badge clarity, sidebar noise, mobile collapse, slot overflow.
Decision at end of P00: pick one shell, keep other as UI theme plugin candidate.

## Pages (static mockups per variant, hardcoded content)
1. Shell + header (campaign name, user, GM preview-as-player toggle), footer slot — visual only.
2. Page view x2 states as separate static shots: non-secret (guest-visible), secret page (owner/GM view with login wall + badge for others). Player view = secrets filtered, `[[secret]]` = redacted, `[!secret]-` hidden, `+` shown.
3. Character + subpage: `characters/mira/` + New subpage button shown only here (non-functional).
4. Sheet slot: same data mocked in 2 visual styles to compare slot layout.
5. VTT-lite: image + fog + 3 tokens + dice tray — static image, no drag/sync.
6. Editor: side-by-side markdown + preview image, `-` red / `+` green, `[!unsupported]` placeholder — no live update.

## Fixtures
Hardcoded HTML/lorem + excerpt styling. No `fixtures/p00/*.md` serving, no DB, no markdown rendering.

## Slots to show
Draw slot boundaries as labeled boxes (`header-right, sidebar-left/right, footer, page-actions, sheet-header`). No slot logic, just layout proof that all variants fit the same slots.

## Pass/fail
- Visual review only: which variant reads best for GM vs new player.
- Secret states distinguishable at a glance (badge/redaction visible in stills, never color-only).
- A11y pre-check per variant: landmarks, focus visible, 4.5:1 text contrast, keyboard path documented. No interaction tests.

## Winner pick (D1, G1 evidence — lane D1 owns this section)
Winner: **Variant B (Focused)**. Stills: `web/static/mockups/b/` (8 stills incl.
one-handed phone sheet `08-mobile-sheet.html` + `a11y.html`); runnable index at
`web/static/mockups/index.html` with 3-pros/3-cons per variant. Loser (A) becomes
a theme-plugin candidate (3-column tree override). F1/F2 build on B's shell:
top nav + single column + collapsible drawer, ledger-style `sheet-header`,
≥44px targets (≥52px phone actions). A11y pre-checks pass per variant
(landmarks, visible focus, 4.5:1, documented keyboard paths).

## Out of scope
Everything functional: auth, SQLite, Datastar/SSE, templ logic, dice engine, conflict UI, markdown parsing, WYSIWYG. P00 produces images/static HTML only; clickable prototype moves to P01.
